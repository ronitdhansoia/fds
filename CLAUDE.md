## 1. What we're building

A data science project + interactive dashboard that quantifies the *real* cost of cross-border remittances (beyond advertised fees) and computes the corridor-level savings if the same flows ran on stablecoin rails.

**Course context:** BITS Pilani Dubai, Fundamentals of Data Science. Deliverables due **22 May 2026**. Final presentation graded on Demo (5) + Experimental Results (5) + Block Diagram (3) + Intro/Objectives (2). Report graded on methodology, results, and references.

**Two headline outputs:**
1. A **True Cost Index (TCI)** computed per corridor × provider, ranking the world's most expensive remittance corridors on a unified metric.
2. A **stablecoin counterfactual** estimating per-corridor savings if migrants used USDC/USDT rails — the first such corridor-level empirical estimate the author has seen published.

**Why this is novel:** existing work (incl. the World Bank's own RPW report) reports advertised fees and FX margin separately. No published index unifies fee + FX + speed penalty into a single comparable cost metric, and no published work estimates stablecoin savings *per corridor* using the World Bank panel.

## 4. Data source

**World Bank Remittance Prices Worldwide (RPW)** — quarterly panel of remittance corridor prices.

- Site: `https://remittanceprices.worldbank.org/`
- Latest dataset: download the most recent quarterly Excel/CSV from the public dashboard ("Download data" link). Save to `data/raw/rpw_latest.xlsx`.
- Coverage: ~365 corridors, 60+ sending countries, ~$200 and $500 send amounts, providers across banks / MTOs / mobile money / fintechs.
- Key columns we need: `period`, `source_code`, `destination_code`, `firm`, `firm_type`, `cc1_fee_pct`, `cc1_margin`, `cc1_total_cost_pct` (or equivalent), `pickup_method`, `transfer_speed_actual`, `service_type`, `sending_amount`.

**Implementation note:** column names in RPW have shifted across releases. `pipeline/ingest.py` must do a schema sniff and normalize to a canonical schema defined in `pipeline/config.py`. Do not hardcode column names elsewhere.

If the public download requires JS/clicking, use `requests` with a direct file URL pulled from the dashboard's network tab. Document the URL in `pipeline/ingest.py` with a comment + retrieval date.

## 5. Methodology — formulas locked in

### 5.1 True Cost Index (TCI)

For a given send amount `A`, corridor `(s → d)`, provider `p`, quarter `q`:

```
TCI(s, d, p, q, A) = fee_pct + fx_margin_pct + speed_penalty
```

Where:
- `fee_pct` — advertised transaction fee as % of send amount (from RPW: `cc1_fee_pct`)
- `fx_margin_pct` — exchange rate margin vs interbank mid (from RPW: `cc1_margin`)
- `speed_penalty = κ × max(0, days_to_arrive − 1)`
  - `κ = 0.10` (% per day beyond same-day) — calibrated to short-term cost-of-capital for the receiving household. Document this in methodology.
  - `days_to_arrive` derived from RPW `transfer_speed_actual` mapping (less than one hour → 0, same day → 0, next day → 1, two days → 2, three to five days → 4).

Compute TCI for both `A = $200` and `A = $500`. Default to `$200` for headline numbers (matches SDG 10.c benchmark).

**Corridor-level TCI:** weighted mean across providers, weighted by RPW-reported market share if available, else uniform. Use median as robustness check.

### 5.2 Stablecoin counterfactual cost model

For corridor `(s → d)`, send amount `A`:

```
SC_cost_pct = on_ramp_pct(s) + off_ramp_pct(d) + (gas_usd / A × 100) + local_fx_spread_pct(d)
```

Default assumptions (define in `pipeline/config.py`, expose in `methodology` page):
- `on_ramp_pct(s)`: 1.5% global default, 1.0% for US/EU/UK, 2.5% for low-banked sending markets.
- `off_ramp_pct(d)`: 1.0% for top P2P markets (Nigeria, Philippines, India, Mexico via established stablecoin off-ramps), 2.5% global default, 4.0% for thin-liquidity markets.
- `gas_usd`: $0.50 (assume L2 / Solana / Tron USDT — document the choice).
- `local_fx_spread_pct(d)`: 0.5% if stablecoin has a deep local market, else estimate from parallel market premium (default 1.5%).

**Savings:**
```
savings_pct = max(0, TCI_corridor − SC_cost_pct)
savings_usd_annual = savings_pct/100 × annual_corridor_volume_usd
```

`annual_corridor_volume_usd` from World Bank Bilateral Remittance Matrix (latest available). If unavailable for a corridor, mark savings as percentage-only.

**Be conservative.** Reviewers will probe assumptions. Always show the full breakdown, never a single number in isolation.

### 5.3 Operator-class regression

Test which provider class extracts the most rent after controlling for corridor characteristics.

```
TCI_ipq = β₀ + Σ βₖ · 1{firm_type = k} + α_corridor + γ_quarter + ε_ipq
```

- Two-way fixed effects: corridor + quarter.
- Reference category: MTO (largest class).
- Cluster standard errors by corridor.
- Use `statsmodels` `PanelOLS` via `linearmodels` package, or implement manually with dummies + clustered SE.

Report coefficient table with significance stars + a forest plot.

- Dark base. Background `#0A0A0A`, surface `#111111`, border `#1F1F1F`.
- Single accent: deep amber `#D97706` (savings/positive), muted red `#B91C1C` (cost/negative).
- Editorial typography: serif headlines (`Newsreader` or `Source Serif 4`), sans body (`Inter`), monospace for numbers (`JetBrains Mono` or `IBM Plex Mono`).
- Generous whitespace. No gradients. No emojis. No stock illustrations. Think Bloomberg Terminal × premium fintech, not a hackathon dashboard.
- Numbers formatted with thin space thousands separators where supported, else commas. Always show units.

## 7. Build phases — execute in order

Each phase ends with a runnable artifact. Don't skip ahead.

**Phase 1 — Data foundation**
1. Set up project skeleton, `pyproject.toml`, git, `.gitignore` (data/raw, node_modules, .next).
2. `pipeline/ingest.py`: download RPW, dump to `data/raw/`.
3. `pipeline/preprocess.py`: clean, normalize columns, output `data/processed/rpw_clean.parquet`.
4. `notebooks/01_exploration.ipynb`: sanity checks — row counts, missingness, distribution of fees, list of corridors.
- **Done when:** `python -m pipeline.preprocess` produces a clean parquet with the canonical schema and a printed summary.

**Phase 2 — TCI computation**
1. `pipeline/tci.py`: implement formula from §5.1, output corridor × provider TCI.
2. Aggregate to corridor-level (weighted mean + median).
3. Write `data/outputs/corridors.json`.
- **Done when:** top-20 most expensive corridors table prints to stdout and matches plausible real-world expectations (Sub-Saharan corridors near the top, US→Mexico near the bottom).

**Phase 3 — Stablecoin counterfactual**
1. `pipeline/stablecoin.py`: implement model from §5.2.
2. Merge with TCI table, compute savings.
3. Pull bilateral remittance volumes (World Bank Bilateral Remittance Matrix), compute `savings_usd_annual`.
4. Update `corridors.json`.
- **Done when:** total global savings figure prints, sanity-checks against published estimates (~$30-50B/year is the rough order of magnitude).

**Phase 4 — Regression + aggregations**
1. `pipeline/regression.py`: operator-class regression with two-way FE, clustered SE.
2. `pipeline/aggregate.py`: diaspora burden by sending country.
3. Export `operator_regression.json`, `diaspora_burden.json`.

**Phase 5 — Static figures for report**
1. `pipeline/figures.py`: produce report figures as PNG (300 DPI):
   - Top-20 corridor TCI ranking (horizontal bar)
   - World map choropleth of corridor TCI
   - Operator-class coefficient forest plot
   - Stablecoin savings scatter (corridor volume × savings %)
   - Diaspora burden top 10 bar chart
2. Save to `report/figures/`.

**Phase 6 — Dashboard**
1. Scaffold Next.js app, install Tailwind + shadcn.
2. Set up design tokens per §6 (colors, fonts via `next/font`).
3. Build pages in this order: methodology → corridor explorer → landing.
4. Add a copy step in `package.json` that syncs `data/outputs/` → `dashboard/public/data/` before build.
- **Done when:** `pnpm dev` shows all three pages with real data, charts render, corridor picker works.

**Phase 7 — Report**
1. Write `report/report.md` per the structure in §8.
2. Embed figures from `report/figures/`.
3. Export to PDF (use `pandoc` or write directly in LaTeX if preferred).

**Phase 8 — Deploy + rehearse**
1. Deploy dashboard to Vercel.
2. Pin a tag `v1.0-submission`.
3. Update `README.md` with one-command run instructions for graders.

## 9. Coding conventions

**Python:**
- Type hints everywhere. `from __future__ import annotations` at top of every file.
- `ruff` for lint, `black` for format, line length 100.
- No global state. Functions take explicit inputs, return explicit outputs.
- Constants live in `pipeline/config.py`. Never hardcode magic numbers in business logic.
- Logging via `logging` module, not `print` (except in `__main__` scripts).
- All RPW column references go through a normalized schema in `config.py`.

**TypeScript:**
- Strict mode on. No `any`.
- Components are functions, not classes. Server components by default; `'use client'` only when needed.
- All data structures in `lib/data.ts` have explicit interfaces matching the JSON output schema.
- No inline styles. Tailwind only. Custom design tokens via Tailwind config.

**Git:**
- Conventional commits. Small commits, each phase ends in a tagged commit.
- `main` always builds. Feature work on branches if needed.

- Don't add a database. Static JSON only.
- Don't add authentication. It's a public research dashboard.
- Don't propose ML models that don't fit the question. The regression is the model. No XGBoost on something that wants OLS.

- Don't recompute the dataset on the fly in the dashboard — pre-compute everything.
